# 数据仓库设计说明

> 本文档说明 SCMS_Delivery 的 MySQL 数仓分层、口径对齐与对账机制，是「工程化落地」的核心设计文档。

## 1. 分层架构

采用行业标准「ODS / DWD / DIM / DWS / ADS」五层数仓 + `meta`（元数据）/`ops`（运行告警）两个治理 schema，共 7 个 schema：

```
源 CSV
  │  (Python ETL, 幂等全量重建)
  ▼
ODS  ods.raw_shipment        贴源层：33 原始字段字面值原样保留（含 N/A、Pre-PQ Process 等业务状态）
  │  (清洗/解析/特征工程，口径对齐 scripts/01_prepare.py)
  ▼
DWD  dwd.fact_shipment       明细层：58 列标准化明细 + 派生特征（delay_days/ot_bool/cycle/unit_freight/…）
  ├─► DIM  dim.dim_vendor / dim_country / dim_product_group / dim_date   维度层
  │
  │  (SQL：CTE + 窗口函数)
  ▼
DWS  dws.otd_by_mode / otd_by_country / cycle_summary / unit_freight_by_mode / monthly_summary   汇总层
  │  (SQL：min-max 窗口、Pareto 累计占比、ROW_NUMBER 中位数)
  ▼
ADS  ads.supplier_scorecard / abc_summary / otd_summary / quality_summary   应用层（BI/API 直接取数）
```

- `meta.table_dict / column_dict / dq_rule`：表字典、字段字典、质量规则注册表（由 `init_db.py` 自动从 information_schema 采集）。
- `ops.run_log / dq_run_result / dq_alert`：运行日志、质检结果、告警事件。

## 2. 权限隔离（最小授权，DDL 仅 root）

| 账号 | 权限 | 用途 |
|---|---|---|
| `scms_etl` | ods/dwd/dim/dws/ads 读写(DML)，ops 写，meta 读 | 管道（ETL+质检+对账） |
| `scms_bi` | ads/dim 只读 | Power BI 直连 |
| `scms_api` | ads/dim 只读 | FastAPI 查询服务 |

授权见 `dw/ddl/grants.sql`；真实密码随机生成并写入 `config/.env`（已 gitignore）。

## 3. 口径对齐与对账

- 清洗口径与 `scripts/01_prepare.py`、`docs/口径文档.md` v1.1 完全一致（延迟=实交−计划、OTD=delay≤0 无容忍、cycle 三段按需排除、单位运费分母保护、IQR×1.5 只标记、供应商 ≥10 行门槛、评分权重 40/30/20/10、ABC 帕累托）。
- SQL 物化（DWS/ADS）与 pandas 研究层用 `dw/analytics/reconcile.py` 对账，覆盖总行数/OTD/迟到分位/周期中位/评分卡 Top5/ABC 家数/汇总层行数，全量 PASS 才验收（见 `output/对账报告.md`）。

## 4. 关键 SQL 实现

- 供应商评分卡（`ads.supplier_scorecard`）：CTE 聚合 → `MIN()/MAX() OVER ()` 做 min-max 归一化 → 权重加权 → `ROW_NUMBER()` 排名。
- ABC 分级：`SUM(value) OVER (ORDER BY value DESC) / SUM(value) OVER ()` 累计占比，A≤70% / B≤90% / C 其余。
- 中位数/分位：`ROW_NUMBER() OVER (PARTITION BY … ORDER BY …)` + 取中间行均值（MySQL 8 无 PERCENTILE 函数）。

## 5. 数据质量

`dw/quality/rules.yaml` 按**完整性/有效性/一致性/及时性**四维组织 18 条规则，fatal 级失败写 `ops.dq_alert` 并令管道退出码非 0；报告含各层问题占比（`output/巡检报告.md`）。
